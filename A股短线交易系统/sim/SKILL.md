# A股短线模拟账户 V1.1

## 1. 定位

本 Skill 是短线交易 Agent 的独立模拟账户系统。

核心原则：

> 行情是真实市场数据，账户是内部虚拟账本，成交必须有明确规则，所有资金和持仓必须可追溯、可对账。

本账户：
- 不依赖东财妙想模拟组合
- 不与长期 Agent 共用账户
- 不读取长期 Agent 的资金、持仓和盈亏
- 不允许长期 Agent 修改本账户
- 不允许短线 Agent 修改长期组合

默认账户：
- 账户名称：A股短线模拟账户
- 账户ID：SHORT_TERM_SIM
- 初始资金：10,000元
- 初始净值：1.0000
- 初始资金可配置

---

## 2. 数据准确性原则

账户不能猜价格、猜成交或用未来数据补成交。

每条行情必须尽可能记录：
- 股票代码
- 股票名称
- 市场
- 行情时间
- 数据时间戳
- 数据来源
- 数据状态

数据质量分级：

### DATA_A
主数据源正常，关键字段校验一致。
允许正常模拟交易。

### DATA_B
主数据源正常，校验源暂时不可用。
允许普通模拟交易，但关键异常交易需谨慎。

### DATA_C
行情延迟、缺字段或局部异常。
允许持仓计算和风险处理；禁止依赖异常数据主动扩大仓位。

### DATA_INVALID
价格、成交量、时间戳等明显异常。
禁止新建订单和模拟成交。

### DATA_CONFLICT
不同数据源关键字段冲突。
暂停依赖冲突字段的新交易，重新读取和校验；未解决前不得编造数据。

## 3. 数据源策略

不绑定单一行情供应商。

流程：

主行情源
↓
关键字段校验
↓
数据质量评级
↓
模拟账户

重点校验：
- 最新价
- 开盘价
- 最高价
- 最低价
- 收盘价
- 成交量
- 成交额
- 涨跌幅
- 涨跌停价格
- 交易状态

关键成交数据尽可能交叉验证。

如果主源异常：
1. 重试
2. 使用经验证的备用数据
3. 标记数据状态
4. 无法确认时禁止成交

## 4. 账户总账

必须维护：

- 初始资金
- 当前现金
- 冻结资金
- 可用资金
- 持仓市值
- 总资产
- 累计盈亏
- 累计收益率
- 当日盈亏
- 当日收益率
- 最大资产
- 最大回撤
- 已实现盈亏
- 未实现盈亏
- 累计交易费用

公式：

总资产 = 可用现金 + 冻结资金 + 持仓市值

累计盈亏 = 总资产 - 初始资金

累计收益率 = 累计盈亏 / 初始资金

当日盈亏 = 当日收盘总资产 - 前一交易日收盘总资产

---

## 5. 资金状态

现金分为：
- AVAILABLE：可用
- FROZEN：订单冻结
- SETTLED：已结算

下单：
可用资金 → 冻结资金

成交：
冻结资金 → 股票成本 + 费用

撤单：
冻结资金 → 可用资金

严禁可用资金为负。

- 股票代码

- 总持仓
- 可卖数量
- 冻结数量
- 当日买入数量

- 交易费用

公式：

持仓市值 = 总持仓 × 最新有效价格

浮动盈亏 = 持仓市值 - 当前持仓成本金额

分批买入必须依据实际成交记录重新计算成本。

## 7. A股T+1

普通A股默认：

> 当日买入，当日不可卖。

总持仓 = 可卖数量 + 当日买入数量 + 冻结数量

当日买入数量下一交易日结算后转为可卖数量。

如果某市场/品种交易规则不同，必须先识别规则，不得套用普通A股规则。

## 8. 订单系统

订单状态：

PARTIAL_FILLED

订单字段：

- 订单类型
- 提交时间

- 手续费
- 状态
- 拒单原因
- 成交依据
- 行情时间戳
- 数据来源

方向：
- BUY
- SELL

V1.1默认模式（市价单）：
- **市价买入/卖出（默认）**：下单时直接用最新行情价成交（MARKET_FILL），无需限价等待、无需持续盯盘。每次 cron 检查时段查一次行情即可成交。
- 限价买入/卖出（可选）：仅当需要指定价格时才用 --type LIMIT。
- 取消未成交订单

V1.1新增：
- 早盘集合竞价（09:15-09:25）：限价买入单若低于开盘价、卖出单若高于开盘价，竞价时段判定无法成交；09:20-09:25不可撤单
- 尾盘集合竞价（14:57-15:00）：深市/创业板/科创板按集中撮合价成交，不可撤单；沪市主板无连续竞价需区分
- 盘后固定价格交易（AFTER_HOURS）：科创/创业板 15:05-15:30 允许按收盘价成交，订单状态支持 AFTER_HOURS_ORDER
- 幂等性：每个订单必须携带 client_order_id（客户端唯一流水号），重复调用直接返回已有订单状态，严禁重复冻结资金或重复建单
- 订单有效期（TTL）：支持 valid_seconds（超时自动撤单解冻），以及 TIF：GTC / IOC（立即成交否则撤）/ FOK（全部成交否则撤）

## 9. 模拟成交

### 市价单（默认，V1.1）
下单时直接按当前最新有效价格成交（MARKET_FILL）。
- 使用方式：`order BUY 600100 100`（不传价格，自动用最新价）
- 优点：不需要限价等待、不需要频繁拉行情盯盘，适合 cron 定时检查模式
- 限制：必须已有最新行情价（先 tick 喂价）；数据无效/冲突/停牌时拒绝成交

### 限价买入（可选）
只有真实市场数据满足预先定义的成交条件才成交。

### 限价卖出（可选）
同样必须满足真实市场数据条件。

### 连续竞价
若封单量大于0（seal_qty>0），买单触及涨停/卖单触及跌停时不得直接成交，模拟订单放入队列尾部（标记排队中）；仅当封单被撤或累计成交量突破时才算成交。无L2盘口逐笔数据时，炸板前的买单按 UNKNOWN_FILL 处理。

### 无法确认
状态为：

UNKNOWN_FILL

不能默认成交。

原则：

> 不使用事后知道的最高价、最低价或收盘结果制造盘中成交。

## 10. K线模拟

如果没有可靠逐笔/盘口数据，只能使用预先定义的K线成交规则。

必须记录：
- 信号时间
- 订单提交时间
- 订单价格
- 当时可获得的数据

例如09:55产生信号，只能使用09:55之后可验证的数据判断成交。

禁止：
- 用当天最低价回填早盘买入
- 用当天最高价证明盘中卖出
- 用收盘后信息模拟收盘前决策

K线成交标记：
SIMULATED_KLINE_FILL

## 12. 交易费用

费用独立配置：

- 佣金率（默认万2.5）
- 最低佣金（默认5元起收）
- 卖出印花税（默认0.5‰，仅卖出单向）
- 过户费（默认0.01‰，沪深双向）
- 其他费用

不要永久硬编码费率（费率在 config.json 可配置）。

买入总成本 = 成交金额 + 买入相关费用

卖出净收入 = 成交金额 - 卖出相关费用

历史交易使用当时适用的费用规则，不因新规则改变历史费用。

### Gross / Net 双重盈亏
- Gross PnL（毛盈亏）：不含印花税/佣金
- Net PnL（净盈亏）：扣除印花税/佣金后的净盈亏
- 账户同时维护 realized_pnl_gross 与 realized_pnl_net，用于评估短线高频策略真实可行性

## 14. 交易前检查

任何模拟交易必须依次通过：

数据质量
↓
交易状态（含涨跌停/停牌/新股临停/ST涨跌幅）
↓
T+1
↓
资金/持仓
↓
订单合法性（含幂等、TTL）
↓
账户风控
↓
策略风控
↓
成交规则

任一失败：
> REJECTED

必须记录拒绝原因。

### 特殊股票状态（V1.1）
- 除权除息（派息/送股/转增）：除权日自动更新持仓成本价与持仓数量，防止除权跳空被风控误判为暴跌止损（corp_action 命令）
- 新股上市前5日无涨跌幅限制（30%/60%临停机制）
- ST/*ST 涨跌幅限制5%（科创/创业板ST为20%），必须动态读取股票类型，不能统一按10%/20%校验

## 15. 账户级风控

默认参数，可配置：

- 单票最大仓位：20%
- 单一题材最大风险敞口：50%
- 正常最大总仓位：80%
- 弱势市场最大总仓位：20%
- 极端市场最大总仓位：10%

单日：
- -1.5%：降低新增仓位
- -2.0%：停止普通新增仓
- -3.0%：INTRADAY_LOCK

最大回撤：
- 5%：降风险
- 8%：暂停主动新增仓
- 10%：ACCOUNT_PROTECTED

账户保护期间：
- 不主动开新仓
- 只允许风险处理
- 完成复盘
- 重新评估后恢复

## 18. 每日结算

收盘后依次：

1. 获取最终有效收盘价
2. 更新持仓市值
3. 计算浮动盈亏
4. 汇总已实现盈亏（Gross/Net）
5. 汇总交易费用
6. 更新现金（含闲置资金计息/逆回购模拟）
7. 更新总资产
8. 计算当日收益率
9. 更新最大资产
10. 更新最大回撤
11. 保存日结快照
12. 执行账户对账

### 现金流分类（Cashflow Ledger，V1.1）
现金细分分类记账：
- TRADE_SETTLEMENT：交易结算资金
- FEE：税费支出
- DIVIDEND：分红入账
- CORP_ACTION：送转等公司行为
- INTEREST：闲置资金计息
- INITIAL：初始入金

对账时将交易费用从毛盈亏中剥离，区分 Gross PnL 与 Net PnL。

## 19. 对账

### 资产对账
现金 + 冻结资金 + 持仓市值 = 总资产

### 交易对账
订单 → 成交 → 资金变化 → 持仓变化

### 持仓对账
昨日持仓 + 今日买入 - 今日卖出 = 今日持仓

### 盈亏对账
期初资产 + 资金变化 + 已实现盈亏 + 未实现盈亏 - 费用 = 期末资产

任何不一致：

ACCOUNT_RECONCILIATION_ERROR

处理：
- 禁止新增交易
- 保留现有持仓
- 定位异常
- 修复账本
- 重新对账
- PASS后恢复

禁止为了让数字对上而直接修改余额。

- 判断股票价值
- 修改交易策略

## 29. 最终原则

1. 不依赖东财妙想模拟组合。
2. 不编造行情。
3. 不编造成交。
4. 不使用未来数据。
5. 不把理论成交当真实成交。
6. 所有成交必须可追溯。
7. 所有资金必须可对账。
8. 对账异常禁止新增交易。
9. T+1严格执行。
10. 历史成交不可直接覆盖。
11. 数据不确定时宁可不成交。
12. 策略和账户风控分离。
13. 正式账户与影子账户分离。
14. 每日结算。
15. 每日对账。
16. 每笔交易留痕。
17. 所有账户数字必须能追溯到资金流水、成交和行情。
18. 订单必须幂等（client_order_id），网络超时不得重复下单。
19. 竞价/涨跌停/盘后等特殊时段必须按对应撮合规则处理，不得按普通连续竞价成交。
20. 除权除息自动调整，防止被误判为暴跌止损。

最终目标：

> 建立一个可审计、可恢复、无未来函数、以真实市场数据为依据的A股短线模拟账户。

## 30. 引擎命令（sim_account.py）

实现文件：`skills/a-share-short-term-sim/sim_account.py`

常用命令：

```
# 初始化账户（默认1万）
python3 sim_account.py init --initial 10000

# 喂行情（真实数据逐笔/K线）并撮合
python3 sim_account.py tick 600519 --price 1500 --high 1520 --low 1480 --session CONTINUOUS --grade DATA_A
# 竞价/盘后：--session AUCTION_AM / AUCTION_PM / AFTER_HOURS / KLINE
# 涨跌停封单：--limit_up 1500 --seal_qty 50000

# 下单（支持幂等 client_order_id、TTL valid_seconds、TIF）
python3 sim_account.py order BUY 600519 100 1490 --model 突破 --client_order_id c001 --ttl 60 --tif GTC --topic 有色

# 撤单 / TTL过期清理
python3 sim_account.py cancel O000001
python3 sim_account.py expire

# 每日结算（收盘价）
python3 sim_account.py settle --closes "600519:1520,000001:10"

# 除权除息：派息 / 送转
python3 sim_account.py corp_action 600519 --type DIVIDEND --cash_per_share 0.5
python3 sim_account.py corp_action 600519 --type SPLIT --shares_per_10 10

# 查询与对账
python3 sim_account.py status          # 实时账户
python3 sim_account.py positions       # 持仓
python3 sim_account.py orders          # 订单
python3 sim_account.py fills           # 成交
python3 sim_account.py cashflow        # 资金流水
python3 sim_account.py reconcile       # 对账（PASS/ERROR）
python3 sim_account.py stats           # 统计
python3 sim_account.py snapshot        # 保存快照
python3 sim_account.py shadow 600519 BUY 100 1500 --reason "策略认为应买" --unfilled "资金不足"  # 影子记录
```

费率与风控参数在 `config.json` 中配置（首次运行生成默认值）。
