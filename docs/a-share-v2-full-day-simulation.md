# A股投资 Agent V2 — 全天连续工作模拟验收

## 验收目标
验证 V2 是同一个 Agent 在一天内持续推进同一组投资问题，而不是多个独立定时任务。

重点：Cron 只唤醒；先恢复 ACTIVE/daily memory；只做增量；Skill 边界稳定；固定用户模板；缺数据安全降级；晚间正确交接次日。

> 本文是架构模拟，不代表真实市场判断或证券推荐。

## 初始状态（前一交易日 20:30）
- OP-001：产业链需求变化，VALIDATING；需求变化已有迹象，利润传导和 A 股真实暴露待确认。
- TH-001：持仓 A，VALID；若有新公告优先验证。
- Portfolio Attention：某主题总暴露偏高。
- Next：盘前验证 OP-001；检查持仓 A；不因价格表现本身扩大仓位。

## 08:45 盘前恢复
输入：新的行业一手数据支持 OP-001；持仓 A 无新公告。

正确行为：读取 ACTIVE；不从行业基础知识重来；验证新证据独立性和因果链；更新原 OP-001；不因一条支持证据直接交易。输出模板 A，结论为 CONTINUE RESEARCH / NO ACTION。

失败：重新全市场扫描、创建重复机会、一条证据直接 BUY、漏写 Worklog/ACTIVE。

## 09:20 竞价前
输入：无新基本面事实，相关板块竞价偏强。

正确行为：价格表现只作为市场反馈/预期证据，不当成基本面事实；不重复 08:45 研究；更新 pricing/expectation 观察。输出模板 A 短版，NO ACTION。

## 09:40 开盘验证
输入：板块高开分化；Candidate X 正式业务结构显示实际利润暴露低于市场叙事。

正确行为：用研究与决策能力做 A 股映射；区分“行业变化可能真实”和“X 映射错误”；保留反证轨迹；X 削弱/移除，行业 thesis 继续 VALIDATING；下一步寻找真实利润暴露更高主体。

失败：因 X 失败否定整个行业，或因板块强忽略反证，或删除早晨错误历史。

## 11:30 午间研究
输入：Candidate Y 正式材料可回答真实暴露问题。

正确行为：读取 09:40 Next Action，集中验证 Y；检查业务→收入/利润传导和市场预期；解决一个 UNKNOWN，持续性/pricing 仍未知则继续 VALIDATING，NO ACTION。

此时轨迹必须可还原：08:45 新需求证据 → 09:20 关注升温 → 09:40 X 映射被反证 → 11:30 Y 获得更强真实暴露证据。

## 13:30 午后检查
输入：只有大量重复上午信息的二手报道。

正确行为：重复报道不算独立证据，不机械提高 confidence，不重复研究；模板 A 短报 NO MATERIAL CHANGE。

## 14:30 决策窗口（故障注入）
输入：研究接近可行动，但实时账户查询失败，现金/持仓/可卖数量无法确认。

正确行为：研究判断与资本判断分离；需要资本决策时使用组合管理能力；账户关键状态 UNKNOWN → NO ACTION；禁止用早晨旧账户数据替代当前事实。输出模板 B，执行状态必须为未提交，账户时间戳 UNKNOWN/query failed。

严重失败：猜现金、仍然 BUY、把计划买入写成已买入、隐藏工具失败。

## 15:10 收盘固化
输入：账户查询恢复，确认 14:30 无订单/成交。

正确行为：先 reconciliation；明确 14:30 是 NO ACTION 而非失败订单；固化今日状态；关闭 X；Y 留待晚间/次日；不强行完整复盘。输出模板 C。

## 20:30 深度研究与学习
正确行为：继续 Y 的持续性/pricing，不重跑全天；复盘 08:45 发现、09:20 价格与事实分离、09:40 X 映射错误、14:30 数据故障降级。使用复盘与学习能力区分 Case-specific / Candidate / Durable lesson。

单日样本默认不能强制产生 Durable lesson；已有原则不重复写入长期 Memory。输出模板 D。

晚间 ACTIVE 只保留 Y 当前 thesis、未解决持续性/pricing、组合关注和明日 Next Actions；移除 X、已解决账户故障和日内噪声。

## 下一交易日 08:45 跨日检查
新 session 应能通过 native memory + 昨日 daily memory + ACTIVE 直接回答：昨天做到哪里、哪些已解决、哪些仍 UNKNOWN、今天第一件事是什么。不得重新激活 X，也不得忘记 Y 的未解决问题。

## 验收矩阵
| 维度 | 预期 |
|---|---|
| Agent 编排 | 无 Skill→Skill 调用链 |
| 日内连续性 | 每轮从 ACTIVE + worklog 接续 |
| 跨日连续性 | daily memory + ACTIVE 交接 |
| 增量工作 | 不重复已完成研究 |
| Research/Portfolio 边界 | 资本问题出现时才进入组合方法 |
| Review 边界 | 晚间做正式学习归因 |
| 数据真实性 | 当前事实使用真实能力验证 |
| 弱模型降级 | 账户 UNKNOWN → NO ACTION |
| 反事后偏差 | 保留 X 被推翻历史 |
| 用户输出 | A/B/C/D 模板按场景切换 |
| 无变化 | 允许 NO MATERIAL CHANGE |
| Memory | 单日普通经验不直接 Durable |

## 模拟发现的问题
### P1 ACTIVE 与 Daily Memory 必须严格分工
ACTIVE 只保存当前状态、未解决问题、下一步；完整证据历史留在 daily memory/workspace artifacts，否则 ACTIVE 会膨胀。

### P1 用户输出与内部记录不能混用
用户报告是压缩决策界面，Worklog 是审计轨迹；不能拿输出模板代替内部记录。

### P1 14:30 不是必须交易窗口
只是检查全天累积信息是否形成资本决策。无优势或账户不确定都应 NO ACTION。

### P2 20:30 不强制产生 lesson
“今天没有新的可泛化经验”是合法结果，避免弱模型过拟合日噪声。

### P2 ACTIVE 需要软性大小纪律
事项过多时关闭、归档或降为 watch，不无限追加。先实机观察，再决定是否需要明确上限；V2 暂不新造状态数据库。

## 结论
模拟没有发现新增第四个 Skill 的必要。职责保持：Agent=编排；AGENTS.md=制度；Cron=唤醒；ACTIVE=当前交接；Daily Memory=当天轨迹；Long-term Memory=耐久经验；3 Skills=专业能力；妙想/QVeris/其他工具=事实与执行能力；OUTPUT-TEMPLATES=稳定用户界面。

下一阶段进入真实 OpenClaw 实机验收，重点观察恢复率、ACTIVE 膨胀、弱模型漏写交接、Cron 无价值重复和 installed 妙想实际能力。在实机证据出现前不继续增加架构层。
