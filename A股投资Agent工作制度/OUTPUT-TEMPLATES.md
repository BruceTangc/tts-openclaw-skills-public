# A股投资 Agent 用户输出协议 V2

## 目的

内部推理、工具调用和工作记录可以灵活，但**给用户的投资工作汇报必须稳定、可扫读、可比较**。模型不得每个时段自由发明输出结构。

输出模板是用户界面，不是内部推理流程。不要为了填满模板制造内容；无内容写"无"或省略明确允许省略的子项。

## 通用规则

1. 第一屏先给结论，不先写长篇过程。
2. 标明本轮时间/任务类型和相对上次的变化。
3. 事实、判断、风险、动作分开。
4. 当前数据无法确认时明确写"未知/未确认"，不得补全。
5. 有资本动作时必须写原因、仓位/组合影响、执行状态。
6. 没有动作时明确写 `NO ACTION`，并说明是"没有足够优势"还是"信息不足"。
7. 不把工具调用日志原样倾倒给用户；只列关键数据源/证据。
8. 除非用户要求详细报告，常规定时汇报保持紧凑。
9. 相比上一时段没有变化的内容不重复大段展开。
10. 用户直接提问时可针对问题回答，但涉及正式投资判断/组合动作时仍保留"结论、依据、风险/未知、动作"四个核心块。

# ⚠️ 渠道格式规则（飞书）

## 事实（已查证）

- 飞书限制的是**单条消息序列化后 30 KB**，不是"表格数量"。
- 超限时 OpenClaw **会自动切分**成多条，**不会整条丢失**。
- 但切分发生在序列化层面：**表格会被从中间切断**，渲染出来是半张表。
- `textChunkLimit` 默认 4000 字符（`channels.feishu.textChunkLimit`）。

来源：`docs/channels/feishu/advanced-configuration.md` §Message limits。

## 规则：表格限长，不是禁用表格

| 场景 | 格式 | 原因 |
|:--|:--|:--|
| **≤5 行**小表（状态、执行结果、单标的多字段） | ✅ **用表格** | 可读性最好，远低于切分阈值 |
| **6~10 行** | ⚠️ 可用，但优先考虑分行 | 接近切分边界，视内容长度定 |
| **>10 行** 或含长文本列 | ❌ **改分行** | 必然被切碎，半张表无法阅读 |
| 周报、多主题深度研究 | ❌ **一律分行** | 内容本身就超限 |

## 分行写法

```
· 某人｜状态｜判断 E2/R1｜本轮：证据增强
· 另一标的｜WATCH｜观望｜本轮：无变化
```

字段用「｜」分隔，一条一行。信息量不损失，只是换排版。

## 主动拆条

单条内容预计超过 **8000 中文字符**（约 24 KB，留安全余量）时，**主动拆成多条**并编号：

```
## 晚间投资报告｜2026-10-23（1/2）
...
## 晚间投资报告｜2026-10-23（2/2）
...
```

不要等系统自动切——自动切不会帮你选断点。

# 模板 A：常规时段汇报

用于 08:45 / 09:27 / 09:40 / 10:30 / 11:15 / 13:30 / 14:30 等固定检查，以及交易时段内其他事件触发的常规汇报。

```markdown
## A股投资工作汇报｜HH:MM

### 1. 本轮结论
· 市场/工作状态：<一句话>
· 相比上次：<最重要的新增变化；无则 NO MATERIAL CHANGE>
· 当前动作：<NO ACTION / CONTINUE RESEARCH / PORTFOLIO REVIEW / 其他>

### 2. 重要变化
· <对象/主题>｜新事实：<>｜判断变化：<增强 / 削弱 / 不变 / 新发现>｜重要性：<高 / 中 / 低>
（无则写「无重要变化」）

### 3. 活跃机会 / Thesis

| 对象 | 状态 | 当前判断 | 本轮变化 | 下一验证点 |
|---|---|---|---|---|
| ... | ... | ... | ... | ... |

（≤5 条用此表；超过 5 条改用分行条目，且只列有变化的）

### 4. 组合关注
· <只有与组合有关时填写；否则写「无新增组合风险/动作」>

### 5. 风险与未知
· <最关键反方、UNKNOWN 或数据缺口>

### 6. 下一步
· <下一时段真正需要继续的 1~3 项>
```

若本轮完全无重大变化（且不满足安静退出的推送例外），可缩短为：

```markdown
## A股投资工作汇报｜HH:MM
· 状态：NO MATERIAL CHANGE
· 组合动作：NO ACTION
· 未解决：<如有>
· 下一步：<下一项>
```

> 完全无变化且满足 `CRON.md` 安静退出条件时，**不推送**，只写一行 worklog。

# 模板 B：资本决策

只要涉及 BUY / ADD / REDUCE / EXIT / PROBE，使用此模板。

```markdown
## 资本决策｜HH:MM

### 决策
· 对象：
· 动作：<NO ACTION / PROBE / BUY / ADD / HOLD / REDUCE / EXIT>
· 结论：<一句话说明为什么现在>
· 研究依据：<E 级 / R 级>

### 依据
· Thesis：
· 新增证据：<必须指出具体是哪条数据、何时取得、与上次决策相比新在哪>
· Reality / Expectation / Pricing：
· 相比上次资本决策发生了什么变化：

### 组合影响
· 当前相关持仓/暴露：
· 调整后的预期影响：
· 集中度/相关风险：
· 机会成本：

### 风险与证伪
· 最强反方：
· 关键 UNKNOWN：
· 减仓/退出/重新评估条件：

### 执行
| 项目 | 内容 |
|---|---|
| 是否执行 | <是 / 否 / 等待> |
| 真实执行状态 | <未提交 / 已提交未确认 / 已成交 / 部分成交 / 失败 / UNKNOWN> |
| 数据/账户时间戳 | |
```

**执行状态不得省略。** 没有真实工具确认，不得写"已成交"。

**若前置门 BLOCKED**：动作行写 `NO ACTION (BLOCKED: <原因>)`，并在依据里说明缺哪个门，不要编造执行部分。

# 输出优先级

当信息很多时，按以下优先级压缩，不能因为篇幅丢掉高优先级内容：

1. 资本动作与执行状态
2. 会改变 thesis 的重大新事实
3. 组合重大风险
4. 关键 UNKNOWN / 证伪
5. 活跃机会状态变化
6. 下一步
7. 次要市场信息

不要用大段行情复述挤占真正的投资判断。

# 推送频率控制

| 场景 | 是否推送 |
|---|---|
| 满足安静退出 4 条件 | 不推送 |
| 触及证伪条件 / E1-R1 机会 / 执行异常 / 账户失败 | 立即推送（模板 B） |
| 常规巡检有增量 | 推送（模板 A） |
| 无增量的常规巡检 | 不推送，只写 worklog |

**每天正常工作日推送上限建议 3~5 条。** 超过说明要么过滤不够，要么在刷存在感。
