## 系统状态机（System State Machine）

全局状态统一管理，每个状态明确允许/禁止的操作，避免 agent 理解歧义：

| 状态 | 触发条件 | 研究 | 买入 | 卖出 | 加自选 | 假设复审 |
|:-----|:--------|:----:|:----:|:----:|:------:|:--------:|
| **NORMAL** | 默认状态，defense_mode=false, intraday_lock=false, API正常 | ✅ | ✅ | ✅ | ✅ | ✅ |
| **DEFENSE** | 组合回撤 ≥ 15% 或 defense_mode=true | ✅ | 🚫 | ✅ | ✅ | ✅ |
| **INTRADAY_LOCK** | 盘中风控检测到异常波动，intraday_lock=true | ✅ | 🚫 | 🚫 | 🚫 | ✅ |
| **API_DEGRADED** | 连续 2 个 Cron 关键 API 全失败 | ⚠️ 仅本地 | 🚫 | 🚫 | 🚫 | ⚠️ 仅本地现有数据 |

**状态切换规则：**
- NORMAL ↔ DEFENSE：由 `risk_control.py` 根据回撤自动切换，或手动标记
- NORMAL ↔ INTRADAY_LOCK：盘中触发后自动锁定，次日开盘前自动解除
- 任意状态 → API_DEGRADED：连续 2 个 Cron API 全失败触发
- API_DEGRADED → NORMAL：下一个 Cron 所有 API 恢复正常后自动解除

**状态传播：**
- 所有 Cron 启动时第一步读取 state.json 确认当前状态
- 状态变更由脚本写入 state.json，LLM 只读不写
- 飞书推送时必须在头部标注当前状态标签（如 `[NORMAL]` / `[DEFENSE ⚠️]`）

## Cron 频率分层（Frequency Bucketing）

**原则：避免 agent「每天找理由交易」。不同频率做不同层级的事。**

| 频率 | Cron | 核心职责 | 禁止做的事 |
|:-----|:-----|:--------|:----------|
| **日频** | #1–#6 | 监控异常、执行已知决策、尾盘优化建仓 | ❌ 修改假设卡 lifecycle<br>❌ 主动改长期判断<br>❌ 深度分析 |
| **周频** | #8（周日） | 行业轮动判断、组合估值变化、假设卡健康度体检、本周操作归因 | ❌ 盘中实时决策 |
| **月频** | — | 组合再平衡（仓位偏离目标 > 5% 时触发）、估值带复核、月度归因 | ❌ 频繁调仓 |
| **季度** | Cron 7（财报季强化） | 财报全面验证、投资逻辑逐条复审、生命周期大迁移、假设卡重大更新 | ❌ 跳过任何 falsifier 检查 |

**日频静默约束：**
无假设更新、无估值带突破、无重大证伪、无系统性风险 → 当日交易类 Cron 直接静默，不推送、不分析、不交易。

**月频执行方式：**
每月第一个交易日 Cron 7 额外执行「组合再平衡检查」：计算各持仓实际仓位 vs 目标仓位的偏离度，偏离 > 5% 且假设卡仍有效 → 生成调仓计划（不自动执行，需次日尾盘确认）。

## 市场环境细分（Market Regime）

用于调整整体风险预算和建仓节奏，**不能单独决定是否持有优秀公司**。

| 市场状态 | 特征 | 风险预算 | 建仓节奏 |
|:--------|:-----|:--------|:--------|
| **牛市** | 指数趋势向上、成交活跃、板块轮动有序 | 正常 | 正常分批建仓 |
| **震荡偏强** | 指数偏强但方向不明、板块分化 | 正常 | 谨慎建仓，偏好回调 |
| **震荡** | 指数横盘、缺乏明确方向 | 降低 | 仅低估+高确定性标的 |
| **震荡偏弱** | 指数偏弱、风险偏好下降 | 明显降低 | 暂停建仓，仅研究 |
| **熊市** | 指数持续下行、流动性收缩 | 极低 | 停止建仓，防御为主 |
| **熊市末期** | 恐慌性下跌后企稳、估值极低 | 逐步恢复 | 小仓位分批研究建仓 |

市场环境判断在 Cron 1（早盘）和 Cron 7（收盘复盘）中更新，写入 `{{OPENCLAW_WORKSPACE}}/tmp/daily_strategy.json`。

### 2. 生命周期管理（与仓位硬绑定）

| 阶段 | 仓位权限 | 操作权限 | 说明 |
|:-----|:--------|:--------|:-----|
| RESEARCH | 0% | 仅研究 | 初步筛选，不进自选或仅标记 |
| WATCH | 0% | 观察 + 可加自选 | 建立假设卡，等待估值或逻辑触发 |
| START | ≤5% | 试探性建仓 | 假设卡初步建立，小仓位验证逻辑 |
| BUILD | ≤10–15% | 允许分批建仓 | 估值进入合理带下沿或逻辑强化 |
| HOLD | 目标仓位（受单票≤30%、现金≥20%约束） | 正常持有 | 假设有效且估值未显著高估 |
| REVIEW | 维持现有仓位 | 只减不加 | 假设出现疑点，进入重新评估期 |
| REDUCE | 只减不加 | 减仓 | 假设部分证伪或估值进入高估带 |
| EXIT | 0% | 清仓 | 假设完全证伪或黑天鹅 |
| COOLDOWN | 0% | 禁止重新建仓 N 个交易日（默认 30–60） | 清仓后冷却，防止情绪化回补 |
| ARCHIVE | 0% | 历史归档 | 已退出但保留假设卡和研究记录供复盘 |

生命周期迁移只在 Cron 7 或周度报告中决策，盘中禁止随意切换。

**⚠️ 生命周期硬约束：**
- **盘中任何 Cron（1-6）只允许「读取」lifecycle 字段，禁止「修改」。**
- **lifecycle 的写操作（包括从 WATCH→BUILD、BUILD→HOLD、任何状态→REDUCE/EXIT/COOLDOWN）一律只在 Cron 7 或周度报告（周日 Cron 8）中执行。**
- 盘中如果判断需要迁移（如黑天鹅触发），只写 RE_STUDY_REQUIRED 标记到 state.json，待 Cron 7 统一处理。
- 违反此规则会导致盘中冲动决策，是 V2.0 最高级别的流程违规。

**禁止出现：持有但不知道为什么持有。**

### 5. 100 分评分体系（量化辅助，与 CheckList 互补）

CheckList 做准入/否决，100 分体系做横向比较与优先级排序。两者互补，不替代。

| 维度 | 分值 | 说明 |
|:-----|:----:|:-----|
| 商业模式 | 20 | 盈利模式清晰度、可复制性、护城河类型 |
| 行业空间/景气 | 15 | 行业规模、增速、竞争格局、周期位置 |
| 竞争优势 | 20 | 品牌/成本/网络效应/转换成本/规模效应/牌照 |
| 盈利能力 | 15 | ROE、净利率、毛利率趋势、扣非净利润 |
| 成长性 | 10 | 营收增速、利润增速、增长来源可持续性 |
| 现金流 | 10 | 经营现金流/净利润比、自由现金流 |
| 管理层/资本配置 | 5 | 诚信记录、资本开支纪律、分红/回购 |
| 估值 | 5 | 当前估值在历史分位与行业相对位置 |

**等级：**
- 90–100：核心候选（优先建仓）
- 80–89：重点候选（可建仓，需更严格估值条件）
- 70–79：观察（进入 WATCH，等待估值或逻辑改善）
- 60–69：谨慎观察（仅 RESEARCH，不进入自选）
- <60：淘汰（不进入任何后续流程）

**硬性否决（任一触发则不得建仓，已持仓触发则 RE_STUDY）：**
- 重大财务造假风险
- 重大退市/ST 风险
- 重大立案或合规风险
- 核心业务出现不可逆恶化
- 现金流长期严重恶化
- 大规模商誉或债务风险
- 管理层重大诚信问题
- 估值明显脱离基本面且缺乏增长支撑
- 无法清楚解释投资逻辑

**评分使用规则：**
- 评分在假设卡创建时计算，每次财报/重大事件后更新
- 评分 > 80 是建仓的必要条件，不是充分条件（还需 CheckList 通过 + 估值在 band 内）
- 评分 < 70 的持仓必须进入 REVIEW 或 REDUCE

### 6. 公司研究框架（基本面穿透）

进入深度研究的公司，必须逐层回答以下问题，不得跳过或倒序：

**第一层：商业模式**
- 公司卖什么？客户是谁？怎么赚钱？
- 利润主要来自哪里？收入增长来自哪里？
- 商业模式是否容易复制？行业是否具有长期需求？

**第二层：行业**
- 行业规模、增速、竞争格局、集中度
- 供需关系、政策影响、周期位置、长期空间

**第三层：竞争优势**
- 品牌、渠道、成本、规模、技术、专利
- 客户粘性、网络效应、资源禀赋、供应链、牌照、管理能力
- **必须回答：这种优势为什么能够持续？**

**第四层：盈利质量**
- 营业收入、净利润、扣非净利润、毛利率、净利率
- ROE、ROIC、经营现金流、自由现金流
- 资产负债率、应收账款、存货、资本开支
- **重点判断：利润有没有转化成现金？**
- 利润持续增长但经营现金流长期明显不匹配 → 降低评分 + 风险审查

**第五层：估值**
- 行业适配估值方法（见下节）
- 至少使用：一个绝对估值指标 + 一个历史估值指标 + 一个行业相对估值指标

### 7. 行业差异化估值方法（详细）

| 行业大类 | 优先估值指标 | 关键财务指标 | 备注 |
|:--------|:------------|:------------|:-----|
| 银行 | PB + ROE | 不良率、净息差、资本充足率 | 低PB高ROE为优质信号 |
| 消费 / 白酒 | PE + FCF + ROE | 净利增速、渠道库存、毛利率趋势 | 关注品牌护城河与渠道健康度 |
| 医药 | PE（历史分位）+ 研发管线 | 研发费用率、在研管线进度 | 创新药看管线，仿制药看成本 |
| 制造 / 工业 | PE / EV-EBITDA + ROIC | 订单能见度、产能利用率、毛利率 | 重资产行业EV-EBITDA更合理 |
| 科技 / 半导体 | PEG + 营收增速 + 研发投入 | 研发费用率、毛利率、市场份额 | 增长阶段用PEG，成熟阶段用PE |
| 新能源 | PE + PEG + 订单/出货量 | 产能利用率、补贴政策、技术路线 | 周期属性强，警惕产能过剩 |
| 强周期（煤炭/有色/化工） | PB + 周期位置 + 库存周期 | 商品价格趋势、库存天数、产能出清 | **禁止**高位用PE追高 |
| 高股息 / 公用事业 | 股息率 + FCF + PB | 分红率、自由现金流稳定性 | 更重稳定性与分红可持续性 |
| 成长股（早期） | PEG / DCF | 营收增速、TAM、用户/客户增长 | PE几乎无意义，看增长质量 |
| 保险 | PEV（内含价值）+ NBV增速 | 新业务价值率、投资收益率 | 保险专用估值框架 |

LLM 在写假设卡时必须声明所用 method。

### 选股层级模型（Fundamental-First Ordering）

**长期投资的选股决策必须严格按以下层级穿透，不允许跳过或倒序：**

```
第一层：公司基本面
  → 行业（赛道规模、生命周期、竞争格局）
  → 商业模式（盈利模式、护城河、可复制性）
  → 竞争优势（品牌/成本/网络效应/转换成本/规模效应）

第二层：财务验证
  → 盈利（营收增速、净利增速、毛利率趋势、扣非净利润）
  → 现金流（经营现金流、自由现金流、资本开支）
  → 估值（在假设卡 valuation_band 内，且行业适配估值方法通过）

第三层：辅助因子（降级使用，不作为主决策依据）
  → 价格（是否在估值带下沿）
  → 均线/量价（仅确认趋势方向，不独立决策）
  → 资金流向（仅作市场情绪参考，不独立决策）
```

**一票否决规则：** 第一层任何一项不通过 → 直接淘汰，不进入第二层。第二层「盈利」或「现金流」任一不通过 → 触发 RE_STUDY，不进入建仓。

   - 价格大幅偏离仅作为触发器，最终决策看逻辑与估值
   - 新选出的优质标的：创建假设卡初稿，计算 100 分评分，进入 RESEARCH / WATCH
   - **RE_STUDY 闭环规则：** 审查完成后，必须：① 更新 `last_reviewed` 为当日日期 ② 追加 evidence_log 记录审查结论 ③ 从 state.json 的 `re_study_list` 中移除对应条目（该条目已处理）④ 如有必要，修改 lifecycle（如 REDUCE/EXIT）。不清除标记会导致重复报警。
⑩ 生成纯文字复盘报告并推送飞书

### 7.1 财报复盘结构化流程（季度财报季强化）

**财报是长期投资的核心验证节点，优先级高于任何价格监控。每次持仓股票发布财报后，必须在最近一个 Cron 7 中执行以下完整流程：**

```
步骤 1: 营收与增长
  → 营收同比/环比增速 → 是否超预期/符合/低于预期
  → 营收结构变化（核心业务 vs 非核心业务占比）

步骤 2: 盈利能力
  → 毛利率同比/环比变化 → 趋势是改善还是恶化
  → 净利率变化 → 扣非净利润（剔除一次性损益）
  → ROE 变化（杜邦分解：净利率×周转率×杠杆）
  → ROIC 变化（衡量真实资本回报效率）

步骤 3: 现金流与资本配置
  → 经营现金流 / 净利润比率（>1 为健康）
  → 自由现金流（经营现金流 - 资本开支）
  → 资本开支是否合理（维护性 vs 扩张性）
  → 负债变化（有息负债/权益比率、短期偿债压力）

步骤 4: 业务与竞争
  → 核心业务市占率/竞争力变化
  → 行业竞争格局变化（新进入者、价格战、政策影响）
  → 管理层表述（年报/季报中的管理层讨论，是否诚实、务实）

步骤 5: 估值重估
  → 盈利预测更新（基于最新财报调整未来2-3年盈利预期）
  → 估值带重估（PE band 是否需要调整）
  → 与假设卡的 valuation_band 对比，是否仍在合理区间

步骤 6: 投资假设验证
  → 逐条检查 key_drivers：是否仍然成立？强化/不变/弱化？
  → 逐条检查 falsifiers：是否有任何一条被触发？
  → 最终结论：逻辑强化 / 逻辑不变 / 逻辑变弱 / 逻辑证伪
  → 根据结论决定 lifecycle 迁移方向
```

**财报后必须输出的结论格式：**
```
📊 {股票名称} {代码} 财报验证结论
投资逻辑：{强化/不变/变弱/证伪}
关键变化：...
估值重估：PE band 调整为 {low}–{fair}–{high}
lifecycle 建议：{维持/升级/降级}（原因）
falsifier 状态：{触发/未触发}（具体条目）
评分更新：{旧分} → {新分}（变动维度）
```

**intraday_lock 时跳过选股与加自选相关步骤，但假设复审仍执行。**

## 自选股体系（A/B/C/D 分类）

所有自选股通过 mx-zixuan 管理，按以下分类标记：

| 分类 | 含义 | 数量控制 | 操作权限 |
|:-----|:-----|:--------|:--------|
| **A类** | 核心长期候选 | ≤ 15 只 | 重点跟踪，随时可进入 WATCH/BUILD |
| **B类** | 重点观察 | ≤ 30 只 | 基础研究完成，等待估值或逻辑触发 |
| **C类** | 研究储备 | ≤ 50 只 | 初步筛选，待深度研究 |
| **D类** | 待淘汰 | 不限 | 逻辑失效或基本面恶化，等待清理 |

每只自选股应在假设卡或 metadata 中记录：
- 加入日期、当前价格、加入时价格
- 投资评分、核心逻辑、合理估值
- 主要风险、当前分类

**淘汰优先级（cleanup_zixuan.py）：**
1. 基本面恶化（盈利/现金流持续下降）
2. 长期逻辑消失（行业空间缩小、竞争格局恶化）
3. 估值失去吸引力（脱离 band 且无逻辑支撑）
4. 研究结论改变（评分降至 < 60）

价格表现只能作为辅助因素，不能单独作为淘汰依据。

## 交易规则（V2.0）

### 买卖定价
全部使用市价单（模拟盘限价不可用）。

### 买入时间与纪律
- 建仓偏好尾盘（14:30–14:50 窗口），但估值与投资逻辑同时满足时，允许在任意 Cron 可交易时段执行（盘中需遵守静默约束与 Cron 频率分层）
- 必须存在有效假设卡 + CheckList 通过 + 评分 ≥ 80 + 估值落在 band 内
- 分批建仓，禁止一把梭
- 单票 ≤ 总资产 30%，永久保留 ≥ 20% 现金
- 同一标的买入后默认冷却期内禁止加仓（防摊薄幻觉）

### 加仓规则
至少满足以下两项才允许加仓：
- 投资逻辑进一步得到验证
- 估值进入合理偏低区域
- 业绩超预期
- 行业景气改善
- 市场预期下降但基本面没有同步恶化
- 竞争优势得到进一步验证

**禁止加仓的情形：**
- 单纯因为跌很多（摊低成本幻觉）
- 为了回本
- 因短期技术面强势而大幅追仓

### 组合级集中度风险
- **单一行业** ≤ 总资产 40%（按申万一级行业分类）
- **单一投资主题** ≤ 总资产 50%（例：AI 主题 = 半导体 + AI应用 + PCB + 服务器，表面 4 只股票实质是同一主题敞口）
- **高度相关资产** ≤ 总资产 50%（过去 60 个交易日相关系数 > 0.7 的持仓视为高度相关）
- 以上集中度约束在 Cron 7 和周度报告（Cron 8）中自动检查，超标时生成调仓建议（不自动执行）

### 卖出时机（优先级从高到低）
1. 黑天鹅强制卖出（ST、立案、造假、退市风险）
2. 假设卡 falsifier 触发且审查确认 → EXIT 或 REDUCE
3. 估值显著突破 band 上沿且基本面无强化 → REDUCE
4. 生命周期进入 REDUCE / EXIT
5. 仓位超标调仓 / 碎股清理

**不再使用**单纯 -5%/-8% 或「连续3天弱于大盘」作为直接卖出指令。

### 减仓规则
以下情况可减仓：
- 估值明显高估
- 投资逻辑变弱
- 盈利预期持续下调
- 行业景气恶化
- 仓位超过组合上限
- 单一主题风险过高
- 出现更高确定性替代标的

**买入：**

**加仓：**

## 策略进化体系（Strategy Evolution Loop）

**本 skill 自带完整策略进化闭环，不依赖任何外部 self-improvement skill。** 进化数据源、触发、处理、沉淀、验证全部在 `{{OPENCLAW_WORKSPACE}}/` 内闭环完成。

### 进化数据源（Inputs）

| 数据源 | 位置 | 用途 |
|:--|:--|:--|
| 投资假设卡 | `{{OPENCLAW_WORKSPACE}}/memory/hypothesis_cards/{code}.json` | falsifier 触发 → 证伪记录 |
| RE_STUDY 标记 | `{{OPENCLAW_WORKSPACE}}/state.json` → `re_study_list` | 待审查持仓/标的 |
| 操作经验库 | `{{OPENCLAW_WORKSPACE}}/memory/操作经验.md` | 待验证/已验证规则沉淀 |
| 交易归因 + 不交易归因 | 当日复盘报告 | 「不买/不卖」的长期验证数据 |
| 复盘三层结论 | T+1 / T+30 / 季度 | 当日执行 → 月度逻辑 → 季度假设 |
| 假设卡 evidence_log | 各假设卡 | 持仓逻辑的审查轨迹 |

### 进化触发（Triggers）

以下任一发生，**必须**进入进化流程（在对应 Cron 的复盘环节执行）：

1. 假设卡 falsifier 被触发（RE_STUDY / REDUCE / EXIT）
2. 同一只标的连续 2 次被 RE_STUDY（说明假设建立阶段就有问题）
3. 同一「不买/不卖」归因标签反复出现（如连续 3 次 #不买-等待更好价格 后仍上涨）→ 说明择时规则需修正
4. 同一规则连续被验证或连续被证伪（进入升级或降级判定）
5. 季度复盘：假设卡逐条 falsifier 检查 + 估值带重估
6. 财报季：财报验证流程发现逻辑失效

### 进化处理流程（Process）

**① 记录**：触发事件发生时，立即在对应载体留下结构化记录：
- 假设卡 falsifier 触发 → `hypothesis_helper.py append-log`（只追加，不覆盖）
- 规则类信号 → 写入 `操作经验.md` 对应规则条目
- RE_STUDY 结案 → 更新 `last_reviewed` + 追加 evidence_log + 从 `re_study_list` 移除

**② 分层判定**：按「经验分层门槛」判断证据强度：
- 单次观察 → 临时假设（仅当天复盘）
- 3–5 次同类样本 → 待验证规则（操作经验.md）
- 10–20 次跨阶段验证 → 已验证规则（MEMORY.md）

**③ 决策**：
- 规则升级/降级**只在 Cron 7 或周度/月度复盘中执行**，盘中禁止修改任何规则。
- 升级前必须补全：适用市场、样本数、成功/失败次数、最大回撤、跨阶段验证记录。
- 被证伪的规则 → 降级或标记失效（保留在文档中注明失效日期与原因，不删除，防止未来重复发明）。

**④ 验证**：
- 每条规则升级后，记录验证起点日期；后续 5–10 个交易日或下一次同类行情检验。
- 若规则在验证期内被证伪 → 回退到「待验证」或「临时假设」，并记录证伪样本。
- 验证结果必须体现在假设卡 evidence_log 或操作经验.md 的样本清单中。

### 规则生命周期（Rule Lifecycle）

```
临时假设（单次）→ 待验证规则（3–5次）→ 已验证规则（10–20次跨阶段）→ MEMORY.md
       ↑                                                          │
       └────────────── 被证伪 → 回退 / 标记失效（注明原因）←──────────┘
```

- 每条规则必须带状态字段：`临时假设 / 待验证 / 已验证 / 已失效`。
- 已失效规则保留在文档中，标注失效日期与原因。
- 禁止：一次成功就改规则、一只股票就改核心逻辑、一个市场阶段就泛化到所有环境。

### 进化输出（Outputs）

每个复盘周期（Cron 7 当日 / 周度 Cron 8 / T+30 / 季度）的末尾，检查并输出：
- 本期触发进化的事件清单（falsifier / RE_STUDY / 归因重复）
- 本期规则新增 / 升级 / 降级 / 失效的记录
- 待验证规则的验证进度（样本数 / 门槛）
- 下一周期待验证项（写入当日复盘报告，供下期 Cron 读取）

### 进化纪律（Discipline）

- 进化只在复盘类 Cron 执行（Cron 7 / 周度 / T+30 / 季度），盘中决策不做规则修改。
- 先记录后决策：任何规则改动前必须有结构化样本记录，禁止凭感觉改策略。
- 假设卡是持仓逻辑唯一合法来源；规则库是策略逻辑唯一合法来源。**两者之外不维护任何隐式策略。**
